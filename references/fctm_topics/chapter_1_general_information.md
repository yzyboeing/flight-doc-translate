# 第 1 章场景：综合信息

## 适用场景

驾驶舱设计与运行原则、训练和评估、机组资源管理、操纵权交接、机动速度和裕度、推力管理、喊话、电子飞行包、显示、结冰、方向舵配平及 FMC 航路核实。只选取可重复使用的短表达。

## 高频句式框架

| English pattern | 中文框架 | 控制点 |
|---|---|---|
| X provides the basis for standardized operations | X 为标准化操作提供基础 | 不扩写为强制标准 |
| there should always be a clear understanding of X | 应始终明确 X | 保留持续要求，不添加执行方法 |
| the crew should verify that X is correct | 机组应核实 X 是否正确 | 保留 `should`，不得升级为法规义务 |
| changes should be made by X and confirmed by Y | 更改应由 X 完成，并由 Y 确认 | 保留分工和先后关系 |
| do not confuse X with Y | 不要将 X 与 Y 混淆 | 两个概念都要明确落词 |
| X is based on A, while Y is based on B | X 以 A 为基础，而 Y 以 B 为基础 | 保留对比关系 |
| X provides an independent means of Y | X 提供一种独立的 Y 方法 | 不误译为冗余系统 |
| select the display that provides X | 选择能够提供 X 的显示 | 不添加模式选择建议 |
| use X as a reference | 以 X 为参考 | 不升级为唯一依据 |
| if X is unavailable, use Y | 如果 X 不可用，使用 Y | 保留不可用条件，不泛化为优先顺序 |

## 易混边界

- `maneuver speed / minimum maneuver speed / command speed / speed bug` 分别处理为机动速度、最小机动速度、指令速度和速度游标。
- `flight path vector / flight path angle / pitch attitude` 分别是显示矢量、航径角和俯仰姿态。
- `recommended callout` 的中文标题可能采用“标准喊话”，但其规范强度仍由英文正文和运营人程序决定。
- `verify / confirm / cross-check` 按核实对象和机组分工译写，不能靠机械一一替换。
