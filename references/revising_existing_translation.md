# 已有中文译稿优化

当用户同时提供英文源文和已有中文 `.docx`，并要求“优化翻译、忠于原文、调整专业术语或保持现有排版”时使用本流程。

## 文件角色

- 英文源文是技术事实、情态、条件、数字、适用性、版权与图表内容的唯一依据。
- 已有中文译稿是待校订文本和版式基线，不是事实来源。原译即使语句通顺，也必须回到英文逐段核对。
- 同版双语资料和 `fctm_zh_usage.md` 只提供同义情况下的表达基准；不得把其中的程序、数值、机型或条件补进英文源文。
- 用户再次提供完全相同的参考资料时，可用文件哈希与逐字比较确认重复；这不改变其版本、修订号和现行性仍需独立核验的边界。

## 开始前确认

1. 分别记录英文源文和中文译稿的路径、文件类型、页数、标题及可识别版本信息。
2. 渲染两者并核对标题、章节顺序、图表数量、图号与结尾内容，确认中文稿确实对应所给英文源文。仅凭相似文件名不得建立对应关系。
3. 若英文源文是在校订过程中后补的，重新执行现行性、编号、适用性、版权和源文版式检查；此前根据二手材料形成的判断不算已确认事实。

## 校订顺序

1. **内容忠实性**：逐段核对遗漏、增补、误译、情态、条件范围、动作主体、比较关系与因果关系。
2. **数字与引用**：逐项核对数字、单位、百分比、速度、距离、图表编号、脚注和交叉引用。发现原文疑似错误时照原文处理并加 `［译注］`，不得静默改正。
3. **术语与场景用语**：在技术含义相同的前提下，按 `fctm_zh_usage.md` 统一表达；先处理概念和语境，再处理词面，不做无条件全局替换。
4. **版式保留**：现有译稿的页面、图表、样式和页脚若已正确，优先做局部修订；只有结构确实妨碍忠实性或可读性时才重建。保留原图比例、版权行和原有视觉语义。
5. **译注审计**：逐条回看英文源页，确认每条译注都有真实疑点且没有替作者改写结论。

## 回归检查

- 生成最终稿后，检查旧译法是否仍有残留，并确认新译法只出现在正确语境。
- 比较校订前后中文稿的数字序列、图表数量、图片数量、段落和表格结构，用于发现意外修改。该比较只是回归信号，不是正确性证明；若旧稿本来有错，必须以英文源文为准改正并记录差异。
- 对混合中英文字体、加粗、颜色或超链接的段落，避免以整段替换破坏局部字符样式。
- 重新渲染全部页面，不得沿用校订前或上一轮输出的视觉 QA 结论。
- 页数变化、图位调整或为保持整块内容而产生的留白，只要不改变内容且已目视确认，可作为版式偏离记录，不应为追求页数一致而压缩文字。

最终仍执行 `SKILL.md` 的“终稿前确认关口”和完整交付清单。
