# FCTM 中文用法路由

本文件是第 1—8 章场景表达模块的总索引。条目由同版中英文 B737 NG/MAX FCTM 在本地对照整理；源 PDF 不属于本 skill，也不得随 skill 分发。

## 使用边界

- 英文待译原文始终决定事实、动作主体、条件、情态、数字、机型和适用范围。场景模块只在含义、对象、阶段和文体相同时提供优先中文措辞。
- 本索引和各模块不是运行批准资料，不保存或复述程序、限制值、连续正文或组织身份信息。不得把短语拼接成原文没有的操作建议。
- FCTM 训练语言不自动覆盖法规、事故报告、适航文件或法律文本。出现冲突时保留待译原文的证据强度和规范性。
- 同一英文词可能因飞行阶段、词性、技术对象或系统构型改变译法。禁止无条件全局替换。
- 模块中的“高”表示同一语境下可优先采用；“语境相关”表示必须回看句子、章节、机型或定义，并视影响进入确认关口。

## 通用动作与状态

| English | 优先中文 | 使用边界 |
|---|---|---|
| monitor | 监控 | 仪表、状态、系统或飞行航径 |
| verify | 核实／确认 | 对照指示、构型或结果；按宾语调整 |
| confirm | 确认 | 不机械与 `verify` 作字面区分 |
| ensure | 确保／确认 | 强调结果时用“确保”，核对状态时可用“确认” |
| maintain | 保持 | 必须完整保留持续条件和终止条件 |
| establish | 建立 | 航径、姿态、推力、构型或稳定状态 |
| apply | 使用／施加／踩 | 舵面用“使用”，力或压力用“施加”，刹车动作可用“踩” |
| select | 选择 | 模式、构型、档位或设定 |
| set | 调定／设置 | 推力、速度、高度常用“调定”；一般参数可用“设置” |
| advance the thrust lever | 前推推力手柄 | 不泛化为“增加发动机功率” |
| retard the thrust lever | 收回推力手柄／将推力手柄收至…… | 保留目标位置 |
| disconnect | 断开／脱开 | 系统连接用“断开”；自动驾驶常用“脱开” |
| disengage | 脱开 | 自动驾驶、自动系统或模式 |
| disarm | 解除预位 | 与“脱开”“关断”区分 |
| extend / deploy | 放出 | 襟翼、起落架、减速板等；具体部件服从惯用语 |
| retract | 收起／收上 | 起落架多用“收起”，襟翼多用“收上” |
| stow | 收起 | 手柄、装置或设备回到收藏位 |
| call out / announce | 喊话／报出 | 标准喊话用“喊话”；状态或位置可用“报出” |
| cross-check | 交叉检查 | 仪表、指示或机组核对 |
| as installed | 如安装 | 仅表示构型条件，不得省略 |
| as required / as needed | 按需／根据需要 | 不增补判断标准 |
| if performance allows | 如果性能允许 | 不简化为“如可用” |
| runway length permitting | 如果跑道长度允许 | 保留前置条件 |
| unless otherwise noted | 除非另有说明 | 保留例外范围 |

## 通用情态与句式框架

这些是翻译框架，不是可脱离源文使用的程序句。

| English pattern | 中文框架 | 控制点 |
|---|---|---|
| maintain X until Y | 保持 X，直到 Y | 不拆散终止条件 |
| after X, do Y | X 后，执行 Y | 保持动作先后 |
| when X is confirmed, do Y | 确认 X 后，执行 Y | 不把确认条件改成同时动作 |
| use X as needed | 按需使用 X | 不增加使用标准 |
| X may be required | 可能需要 X | 不升级为必须 |
| X should be used | 应使用／建议使用 X | 按全文规范性选择，不升级为必须 |
| X must be considered | 必须考虑 X | 保留强制性 |
| X is recommended | 建议 X | 不改成“必须” |
| X is not recommended | 不推荐 X | 不自动改成“禁止” |
| do not attempt to X | 不要试图 X | 只有 `must not/shall not` 才可升级为“不得” |
| unless X occurs | 除非发生 X | 保留例外范围 |
| if X becomes a problem | 如果 X 成为问题／如果出现 X 问题 | 结合宾语自然化，不改因果 |
| runway conditions permitting | 如果跑道条件允许 | 保留条件 |
| is sufficient to X | 足以 X | 不夸大为“保证” |
| contributes to X | 有助于 X | 不译成确定因果“导致” |
| may result in X | 可能导致 X | 保留可能性 |
| prevent / avoid | 防止／避免 | 核对动作主体和结果对象 |

## 必查概念边界

- `guideline / recommendation / limitation`：指标、建议和限制不得互换。
- `may / should / must`：可能、建议和必须不得互相升级或降级。
- `flight path / track / course / glide path / glideslope`：航径、轨迹、航道和信号束必须按技术对象区分。
- `speedbrake / spoiler / ground spoiler`：操纵系统、部件和地面功能不可机械统一。
- `braking action / effectiveness / capability / force / pedal pressure`：效应、能力、力和脚蹬压力分开处理。
- `reverse thrust / thrust reverser / reverse idle`：推力、装置和位置分开处理。
- `engine failure / engine inoperative`：失效事件与不工作状态分开处理。
- `go-around / missed approach`：都可译为“复飞”，但动作与程序结构不得合并。
- `firm touchdown / hard landing / bounced landing`：坚定接地、重着陆和跳着陆不可混同。
- `upset recovery / stall recovery`：复杂状态改出与失速改出不可混同。
- `slippery / wet / contaminated runway`：滑跑道、湿跑道和污染跑道不可互换。

## 每次使用前核对

1. 是否为同一技术对象、动作、飞行阶段和文体；
2. 译法是否改变情态、程度、条件、否定或适用范围；
3. 待译原文是否另有定义或统一用法；
4. 是否存在机型、系统构型、运营人用语或监管体系差异；
5. 语境相关条目是否已经进入初始方案或终稿前确认清单。
