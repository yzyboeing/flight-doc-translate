# 术语冲突与决策边界

本文件保存会影响翻译决策的稳定冲突。它不保存来源页码或长句；当前任务若出现未覆盖的冲突，应进入初始方案或终稿前确认。

| 英文项 | 可能译法 | 决策边界 | 默认处理 |
|---|---|---|---|
| verify / confirm / check | 核实／确认／检查 | confirm 在 QRH 可表示双人动作前口头一致；verify 常核对状态；check 常为检查动作 | 按技术对象和文体拆分，禁止全局替换 |
| Condition / condition | 状况／条件 | QRH 标题字段用“状况”；逻辑从句通常用“如果／当／在……条件下” | 先判断字段还是逻辑关系 |
| Objective / objective | 目的／目标 | QRH 字段说明用“目的”；性能目标或控制目标可用“目标” | 服从文档定义 |
| set | 调定／设置／置于／刹住 | 参数、选择器、控制件和刹车动作不同 | 与宾语和目标状态绑定 |
| select | 选择／选择至 | 模式选择与控制件移位不同 | 不替代 set 或 move |
| close | 关闭／关／收回／收光 | 活门、开关、门和推力手柄不同 | 必须记录控制对象 |
| pull | 拉／提起／拔出 | 手柄、火警电门和跳开关不同 | 按部件机械动作处理 |
| trip / tripped | 跳开／已跳开 | 系统动作、跳开关状态和故障标题可能不同 | 区分动作与状态 |
| disengage / disconnect | 脱开／断开 | 自动飞行设备多用“脱开”；电气或机械连接可用“断开” | 服从系统对象 |
| arm / disarm | 预位／解除预位 | 不等同于接通／关断 | 保留系统状态 |
| land at nearest suitable airport | 在最近合适机场着陆 | 指令强度高于计划表述 | 不增删“计划” |
| plan to land at the nearest suitable airport | 计划在最近合适机场着陆 | 表示计划，不等于立即执行 | 保留 plan to |
| immediate landing / land immediately | 立即着陆 | 紧迫程度高于“尽快”或“最近合适机场” | 不弱化 |
| Checklist Complete | 检查单完成 | 表示完成状态或完成符 | 与“完成检查单”动作区分 |
| Checklist Complete Except Deferred Items | 除延迟项目外，检查单完成 | 明确保留例外范围 | 不简化为“检查单完成” |
| annunciated / unannunciated checklist | 显示／非显示检查单 | 指有无相应警报或指示，不等同正常／非正常 | 保留成对概念 |
| airplane effectivity | 飞机有效性／飞机适用性 | QRH 栏目用法可为“有效性”；一般审查常用“适用性” | 按栏目和说明文体区分 |
| warning / caution / note | 警告／注意／注 | 等级和作用范围不同 | 保留原等级和视觉层级 |
| may / should / must | 可能／应／必须 | 证据和义务强度不同 | 不升级、不降级 |
| do not / must not | 不要／不得 | 一般禁止动作与强制禁止的强度可能不同 | 先看全文规范体系 |
