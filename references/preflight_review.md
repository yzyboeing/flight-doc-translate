# 双确认与交付审核

正式航空技术资料默认经过初始方案和终稿前两个暂停关口。本文集中保存能力自检、材料预审、确认格式和交付要求；`SKILL.md` 只保留路由与不可省略的主流程。

## 能力自检与路线

每次任务开始实测，不沿用上次结果：

1. 实测 DOCX 生成库能否加载。本仓库不含 `package.json` 与 `node_modules`，`require('docx')` 需要用 `NODE_PATH` 指向已安装该依赖的目录，或在任务工作目录先 `npm install docx`；不得因为「本机装过」就推定可加载。
2. 源 PDF 能否用 Poppler、PyMuPDF 或等效工具渲染，图片能否处理；
3. DOCX 能否渲染为逐页图像。**两条等效路径，用可用的那条**：环境提供 `documents` skill 时用其当前流程；否则用 LibreOffice + Poppler（`soffice --headless --convert-to pdf` → `pdftoppm -jpeg -r 85`）。两条都不可用才算本项失败。
4. CJK 字体能否被生成和渲染链实际解析：按 [DOCX 制作与视觉 QA](docx_production.md) 生成一页中文烟雾测试并目视检查，不能只根据字体名称或系统安装列表推断。

- **完整路线**：四项均通过，可制作 DOCX、提取或裁切原图并完成全页视觉 QA。
- **字体待修复**：前三项可用但第 4 项失败时，先修复字体映射并重测；仍失败只能交付标为“未完成字体与视觉 QA”的结构性草稿，不能称为终稿。
- **受限路线**：不能生成 DOCX 或不能渲染源 PDF 时，开始翻译前明确报告缺失能力。只有用户接受后才交付 Markdown／纯文本，不得假装完成 Word 成品。
- **仅缺 DOCX 渲染**：只能交付标为“未完成视觉 QA”的结构性草稿，除非用户明确接受，否则不称为终稿。

受限路线交付 Markdown／纯文本时，SD-4 仍适用：不把复核声明插入译文正文或译文文件，而是在对话中的独立“交付说明”末尾写出规定声明。

## 初始方案触发与停止点

- 默认触发：完整 PDF、技术通告、训练或运行手册、事故报告，以及包含安全关键数字、图表、警告或复杂版式的材料。
- 用户明确说“直接翻译／无需初始方案确认”时可跳过本关口；终稿前确认仍保留。
- 用户明确要求“一次完成且无需任何中途确认”时才可跳过两个关口；内部检查不得跳过。
- 提交《初始翻译方案》后必须停止。只有用户明确确认后才可翻译全文或生成正式 DOCX；沉默不构成确认。
- 关键页缺失或不可辨、缺失信息会改变当前段落技术理解或约定用途、或明确授权限制不允许当前操作时，报告并暂停受影响部分，不提交假定可执行的方案。身份或适用性字段未提供本身不自动阻断整份材料：记录“未提供”，不推定；其余可辨内容按已确认范围处理。无法核实现行性不等于不能制作说明核验边界的学习参考译本；明确的使用及传播限制仍须遵守。
- 形成任何问题清单前读取 `standing_decisions.md`；已有长期结论的项目直接执行，不重复询问。

## 材料阅读与完整性

形成方案前应阅读完整材料，至少完成全文文本抽取或 OCR、全部页面缩略图检查，以及首页、修订记录、目录、适用性、警告、图表密集页和结尾页的原尺寸复核。不得只看封面或若干抽样页就宣称已掌握全文结构。

对扫描件、长截图或拼接截图同时检查：

- 页码、章节号、段落末尾和下一段开头是否连续；
- 是否有重复带、异常接缝、顺序倒置或缺段；
- 一个截图／图层是否遮住另一个，造成页面外观看似完整但正文实际被覆盖；
- OCR 字数或页面尺寸异常是否对应可见缺失。

发现遮挡或缺失时报告确切可见范围并停止受影响部分；不得根据上下文补写被遮挡内容。

## 《初始翻译方案》

### 1. 材料身份与边界

- 文件、标题、正式编号、修订号、日期、页数和页面尺寸；
- 机型与正式适用性字段；正文建议范围不得提升为正式适用性；
- 文本可提取性、扫描质量、缺页、重复页、拼接遮挡或不可辨内容；
- 版权、专有和出口管制标识及已知授权边界；
- 现行性结论，以及只能由制造商受控渠道或文件所有方确认的事项。

逐项标记“已确认／合理推测／无法验证”。文件名、PDF 元数据和页数相近都不能单独证明编号、版次、双语对应或授权范围。

- 首页、编号表和适用性字段必须回看页面图像逐字核对，不能相信文本抽取的行列顺序；缺少正式字段时记录“未提供／不适用”，不从文件名推定。
- 可访问公开权威来源时核实现行性；制造商受控文件不能仅靠公开网页证明现行。发布日期距当前超过 3 年且无法核实时，明确报告“无法独立核实是否为现行版本”，未获确认时只可作为带过期风险说明的参考译本。
- 未发现专有、出口管制或复制授权文字只表示“未发现”，不等于公有领域或已获传播许可。

### 2. 翻译目标与事实来源

- 说明用途、读者、是否打印和输出格式；页面固定为 A4（SD-1），不再询问 A4／Letter；
- 指明英文技术事实来源，以及已有中文译稿、双语资料和术语模块的角色；
- 识别训练指导、运行程序、法规、事故调查或技术说明等文体，不让一种文体覆盖另一种文体的规范性或证据强度。

### 3. 专业术语与句法预审

只列会影响一致性、理解或安全含义的真实问题，使用：

`编号｜原文术语／短语｜建议译法｜备选译法｜语境与歧义｜把握度｜理由｜影响范围`

- 包括同词多义、部件／事件、动作／状态、能力／效果以及 `may/can/should/must`、否定、条件、程度和范围；
- 列出动作主体、指代、并列关系、条件覆盖或因果关系可能存在的多种理解；
- 原文疑似错字、错号、单位、数字或交叉引用时，建议始终是“正文照译；疑点进入终稿前确认和交付说明”，不得建议加译注或静默修正；
- 给出可直接采用的建议，不把未经对照的推测写成既定术语，也不堆入无须决定的普通词汇。

### 4. 版式、图表和 QA 路线

- 单栏、A4、装订边、字体和黑白／彩色路线；
- 图片直接提取或整页裁切、图内英文对照方式；
- 表格重建、保留原图或横向页面的选择；
- 目录、原有页眉页脚、脚注、警告框和交叉引用的处理；
- 预计页数／图位变化，以及无法像素级复刻的部分；
- 数字、单位、否定、条件、情态、警告等级、图表编号、CJK 字体和全页渲染检查；
- 执行阶段新发现的问题进入终稿前确认，不由译者静默决定。

所有待决定事项带建议选项，使用户可以回复“全部按建议执行”或只修改指定编号。

## 终稿前确认

完成全文草稿、内容双遍复核和第一轮全页视觉 QA 后，集中提交执行阶段新增且确需用户决定的问题，然后停止：

- 使用“编号｜类别｜建议选择｜理由｜影响范围”；总数不超过 10 条，超过时先合并同类项；
- 按需覆盖低把握度术语、原文疑点、图位／宽表／目录、原文采样色、现行性、适用性和用户指定的保留范围；
- 已由 `standing_decisions.md` 或初始方案确认的事项不再询问；
- 没有未决问题时明确写“无未决问题”，仍询问是否按当前草稿定稿并停止；
- 确认时提供本次待批准草稿的文件链接或完整可审阅预览，标明版本和已完成检查；审核稿属于批准所需材料，不受最终交付格式限制。同一版本已经明确批准且内容、版式未变化时，不重复请求定稿批准；
- 用户答复造成内容或版式变化后，重新执行受影响检查；最终交付前重新渲染全部页面。

## 对话交付说明

最终交付时，完整路线只交付最终 DOCX，除非用户另要中间件；前述批准关口仍须提供可审阅草稿。受限路线按已获接受的格式交付。对话交付说明包含：

1. `fidelity.md` 交付前清单的逐项结论；
2. 单栏、A4、页数、图位、宽表和无法重建内容等版式偏离；
3. 术语存疑清单及建议核对的受控资料；
4. 原文疑点清单：位置、疑点、可核验依据和“正文照译”的处理结果；
5. 机型适用性、文档编号、日期、修订号和现行性核验边界；
6. 版权、专有及出口管制处理；
7. 受限路线未生成 DOCX、未提图、字体未验证或未完成视觉 QA 的具体项目；
8. 本次维护状态：已授权维护的回写摘要与验证状态，或未执行维护时的候选建议；无合格经验时明确说明；
9. 最后原样写出：**本译文未经技术复核，仅供学习参考，不得作为运行依据。**

第 9 项只存在于对话交付说明中，不写入译本纸面、DOCX、Markdown 或纯文本译文（SD-4）。
