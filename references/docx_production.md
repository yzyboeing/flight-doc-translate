# DOCX 制作与视觉 QA

需要生成、校订或验证 Word 译本时完整读取本文件；只交付纯文本时不加载。

## 文档评估

- 用 `pdfinfo`／`pypdf` 记录页数、页面尺寸、加密状态、文本可提取性、字体与图像情况；用 `pdffonts` 或等效工具检查字体。
- 渲染全部页面或制作低分辨率 contact sheet，识别单／双栏、标题层级、表格、脚注、页眉页脚、警告框与插图边界。
- 对拼接截图、扫描合成页和覆盖图层额外检查：页码／段落序列是否连续，是否存在重复带、接缝错位、透明或不透明图层遮挡、上段覆盖下段、看似完整但实际缺失的内容。发现后把它视为源材料缺陷，不猜测被遮挡文字。
- 原文黑白时使用 `scripts/style_mono.js`，不得新增彩色强调。原文彩色时先运行 `scripts/sample_colors.py`，再配置 `scripts/style_boeing.js`；未确认采样色时不得自行选色。
- 正文单栏，页面一律 A4（SD-1）。保留信息层级、图表次序和原有视觉语义，不为追求页数一致压缩字号或改变内容。

## CJK 字体能力

在第一次生成正式 DOCX 前验证实际渲染链，而不是只检查字体名称：

1. 确认生成工具能够解析至少一种中文衬线字体和一种中文无衬线字体；
2. 生成含中文、全角标点、负号、温度符号和英文缩写的单页烟雾测试；
3. 用正式 DOCX 渲染工具转成页面图像，目视确认无方框、缺字、错误字体回退或标点基线异常；
4. 失败时先运行 `scripts/fontconfig_for_macos.py` 或选择当前环境真实可用的 CJK 字体后重试。仍失败则降为结构性草稿路线，不得等到全文 QA 才首次报告。

目标环境有指定字体时，可用 `FLIGHT_DOC_SERIF_CJK` 和 `FLIGHT_DOC_SANS_CJK` 设置；任何替代都记录并在终稿全页渲染中复核。

## 图与表

1. 先用 `pdfimages -list` 判断位图能否直接提取；矢量图通常通过整页渲染后裁切。
2. 可使用 `python scripts/extract_figures.py source.pdf work/figures --dpi 200`，再用 `--crop PAGE:X0,Y0,X1,Y1[:NAME]` 记录可重复裁切参数。
3. 每张裁图目视检查边界、清晰度、纵横比、图题残留和遮挡。图、图题与图内标注对照表保持相邻。
4. 大于 6 列的宽表避免跨页拆行；需要横向节或分页时不得凭空创建表题。

## 样式与生成

- 从本 skill 的 `scripts/` 直接引用样式模块，避免复制后漂移：黑白稿用 `style_mono.js`；彩色稿用经过原文采色配置的 `style_boeing.js`。
- `page_setup.js` 提供 A4、装订边和目录组件。页眉页脚按原文还原（SD-2）；`buildFooter()`、复核状态横幅与版本块保留但默认不调用（SD-2、SD-4）。
- 正文西文 Times New Roman、中文宋体类、10.5 pt；彩色刊物可用 Segoe UI／微软雅黑类。表格线 0.5 pt，黑白稿表头不新增底纹。
- 中文使用全角斜杠“／”和破折号“——”；图表编号写作“图 1”“表 1”。字符样式转换不得改变引文内容、英文标签或链接范围。
- 文件名使用英文或拼音。

## 全页 QA

使用 `documents` skill 的当前 `render_docx.py` 把 DOCX 渲染为逐页图像并实际查看全部页面。至少检查：

- 中文字体无方框、缺字或错误回退；标题和正文无裁切、重叠、孤行；
- 拼接或裁切图片没有覆盖相邻内容、重复条带、接缝错位或被遮挡段落；
- 表格列宽、合并、跨页、重复表头和脚注正确；
- 图像比例和清晰度正确，图、图题和标注对照关系清楚；
- 页眉页脚与原文一致，未添加原文没有的编号、复核状态或页码；
- 黑白稿无新增颜色，彩色稿只使用已确认的原文颜色；
- 数字、单位、限制、警告等级、图表编号和交叉引用与原文一致。

修改任何内容或版式后重新渲染受影响页面，并在最终交付前重新渲染全部页面。结构检查、解压检查或“页面看起来完整”都不能替代逐页内容连续性检查。
