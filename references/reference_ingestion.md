# 双语手册导入与 Skill 优化

用户提供 FCTM、QRH、FCOM、SOP 或其他现有手册并要求完善本 skill 时使用。本流程只提取能够改变后续翻译决策的短术语、搭配、抽象句式和 QA 规则，不复制手册。

## 第一阶段：只读审核与暂停

1. 保持源文件不变，在任务工作目录抽取文本、渲染必要页面并检查完整性。
2. 核对标题、正式编号、修订号、日期、页数、页面尺寸、适用性、有效页清单、版权、专有和出口管制标识。
3. 判断双语资料是全书可对齐、章节可对齐，还是只能提供中文风格候选。文件名相似和主修订号相同不足以证明逐条对应。
4. 按文档类型界定提取范围：FCTM 侧重训练和飞行阶段表达；QRH 侧重检查单结构、动作、控制状态和条件分支；FCOM 侧重系统与程序；SOP 只在适用性明确时提供运营人语言。
5. 检查现有条目是否重复、冲突或放错文体。
6. 向用户提交《Skill 优化方案》，列出来源角色、拟新增模块、冲突处理、公开边界和验证方法，然后停止。只有用户明确确认后才能进入第二阶段。

## 第二阶段：提取与分级

1. 先建立任务内私有证据表，再写公开规则。证据表可记录来源身份、页码、版本和哈希，但不得加入公开仓库。
2. 以短语或抽象句式为最小单元；不得保存连续正文、连续标题、完整检查单、程序步骤、性能数据或限制值。
3. 每个候选记录：

   英文｜首选中文｜备选中文｜技术对象｜文档类型｜飞行阶段／系统｜典型搭配｜使用边界｜状态｜把握度

4. 逐项核对动作主体、技术对象、条件、否定、情态、程度、顺序和适用性。全部一致才可标记“已对齐”。
5. 只有实际计数过的表达才能称为“统计高频”；未计数但明显可跨材料复用的内容称为“高复用价值”。
6. 中文独有的运营人页面只提取去身份化的风格规律，并标记“风格候选”；不得反推英文或提升为制造商标准。
7. 差异可能影响飞行员理解时写入冲突台账，不强行统一。

## 第三阶段：写入、验证与发布

1. 把条目放到最窄的路由位置；入口文件只保留选择规则，不堆积词汇。
2. 运行结构、链接、字段、术语冲突、公开内容和代表性行为检查。
3. 确认公开目录不含源 PDF、抽取文本、页面图像、长段原文、组织身份、内部编号、机号、页码、哈希或本地路径。
4. 更新本机安装版后重新验证，确保与公开工作副本一致。
5. 仅在用户对当前任务明确授权，或明确指定持续维护仓库时，才同步外部仓库；推送后核对远端提交。
6. 若无合格条目，不为制造版本变化而提交空更新。

## 版本更新

- 新版资料不得静默覆盖旧用法。先判断差异是技术修订、编辑调整还是中文风格变化。
- 技术含义发生变化时，旧条目标记废弃或限定版本；无法判断时保留冲突。
- 私有证据台账用于追溯，不是普通翻译任务必须加载的术语库。
